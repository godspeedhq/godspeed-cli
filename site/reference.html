Commands

Making and building

CommandWhat it does
new service <name>
new library <name>		Create the smallest valid project of that kind, against the OS release you build with. --dir puts it elsewhere. utility, app and driver are refused, with the reason: GodspeedOS cannot run those kinds yet.
checkValidate the project, its toolchain pin, its stdlib release, and its contract against the OS's schema - without building.
build [--arch <isa> | --all]Build for one architecture (default x86_64; also aarch64, armv7, riscv64) or every one the OS supports. A service gives one ELF per architecture; a library, an rlib.
testRun a library's tests on your workstation. Refused for a service, which cannot run off a Godspeed machine.
runRefused, with the reason: GodspeedOS has no public way yet to run a service built outside its tree.
doctorCheck your environment: this CLI's version against the latest release, the OS checkout, the pinned toolchain, every target, QEMU. Says the command that fixes each problem.

This CLI itself

CommandWhat it does
self updateDownload the latest release's build for this machine and its SHA256SUMS, check one against the other, run the new binary, and only then swap it in, in one rename. A checksum mismatch, or a binary that does not run, changes nothing.
self uninstall [--yes]Remove this binary, the installer's folder and the PATH entries the installer added, after listing them and asking. Keeps your configuration directory: your signing key, tokens and trust records.

A copy built with cargo install belongs to Cargo; both commands point you to Cargo instead.

Packaging and verifying

CommandWhat it does
package [--arch <isa>] [--out <dir>]Build every architecture and write a package directory (default target/package/<publisher>-<name>-<version>), then verify it from disk before reporting it. Needs publisher in godspeed.toml.
verify <dir>Check every file of a package directory against its manifest, and its signature if it has one. Needs no OS checkout and no registry.
sign <dir>Sign a package directory with your key (writes manifest.sig) and verify the result. publish does this for you.
fetch <publisher/name>[@version] [--out <dir>] [--trust-root sha256:...]Download a release (default: the highest version) and verify it through the registry's whole chain of trust before keeping it.

Publishing

CommandWhat it does
key generateMake your Ed25519 signing key. Never replaces an existing one.
key showPrint your public key, for the registry maintainer.
login [--with-token]Make a publisher token on this machine, store it, and print its fingerprint for the maintainer to approve. Again later: says whether it is approved. --with-token stores an existing token instead, read from the terminal or standard input, after checking it.
token newMake a token for CI: printed once, stored nowhere.
whoamiYour account, the namespaces you may publish under, and when your token expires.
publishPackage, sign, reserve, upload and finalise. If finalising gets no answer, reads the registry's index and reports what it finds. Always safe to run again.
logoutRevoke the token at the registry and remove it from this machine.

Belonging to a Godspeed machine

install, search, info, list, update and uninstall belong to the native package manager, a separate program that runs on a Godspeed machine. This CLI recognises them and says so (exit 22), rather than doing something else under their name.

Options every command takes

OptionMeaning
--os <path>The GodspeedOS checkout to build against. Default: GODSPEED_OS.
--registry <url>The registry. Default: GODSPEED_REGISTRY, then the last login.

Environment variables

VariableMeaning
GODSPEED_OSPath to a GodspeedOS checkout: its stdlib release, pinned toolchain, targets and contract schema. Read, never written.
GODSPEED_REGISTRYThe registry URL.
GODSPEED_TOKENA publisher token, in place of the stored one (for CI).
GODSPEED_SIGNING_KEYYour signing key's secret, in place of signing-key.toml (for CI).
GODSPEED_CONFIG_DIRWhere the CLI keeps its files, in place of the default below.
GODSPEED_NO_UPDATE_CHECKSet to 1 to stop the once-a-day check for a newer release. It is also skipped when CI is set or stderr is not a terminal.

Files

In ~/.config/godspeed/ (or $XDG_CONFIG_HOME/godspeed/; on Windows %APPDATA%\godspeed\), each readable by you alone:

FileHolds
signing-key.tomlYour signing key. Back it up; never share it.
credentials.tomlYour token for each registry, and which registry is the default.
update-check.tomlWhen this machine last asked for the latest release, and the answer. Delete it and the next command asks again.
trust/For each registry, the root of trust this machine accepted and the newest metadata versions it has seen, so it can never be sent back to older ones.

A project's files

godspeed.toml           # what kind of project this is, where its contract is, and the publisher,
                        # description and license a package of it carries
Cargo.toml              # how Rust builds it; depends on the `godspeed` stdlib at an OS release tag
contracts/<name>.toml   # (services) the OS service contract: the authority it REQUESTS
rust-toolchain.toml     # the compiler that OS release is built with
src/

And a package directory, as package writes it and verify checks it:

manifest.toml           # name, version, kind, publisher, and the size and SHA-256 of every file
manifest.sig            # the publisher's signature over the manifest
contract.toml           # (services) the contract, as built
x86_64.elf  aarch64.elf  armv7.elf  riscv64.elf

The format is defined in package-format.md, independent of any registry.

Exit codes

Scripts and CI can tell failures apart without reading the text.

CodeMeaning
0Success
2The command line itself was wrong
10Invalid project
11Environment: no OS checkout, toolchain or target missing
12Unavailable target or architecture
13A dependency could not be fetched
14Compilation failure
15Test failure
16Invalid package: a missing or extra file, a manifest that breaks the format
17Integrity failure: a size or checksum mismatch
18Authentication failure: not logged in, or the token is unknown, revoked or expired
19The registry (or, for self update, GitHub) could not be reached, before anything was changed
20GodspeedOS does not provide this yet
21This CLI does not implement this yet
22This is the native package manager's command, not this CLI's
23Permission denied: the namespace is not yours, or the key is not listed for it
24Conflict: the version is already published, or being published
25Outcome unknown: finalising got no answer and the index does not show it yet - run publish again
26Signature failure: a signature is malformed, or the named key did not sign this manifest
27Untrusted: the registry's signed metadata does not vouch for it - an unknown, retired or revoked key, or metadata that is unsigned, expired, rolled back or inconsistent
28Not found: the registry has no such package, or no such version of it
29Cancelled: you declined, or there was no terminal to ask and --yes was not given; nothing was changed
30A local file could not be read or written
